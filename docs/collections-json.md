# Подборки: JSON-обмен и резервное копирование

Статус: реализовано в AppShelf 2.17.0. Описанные JSON-обмен и резервные копии работают локально, без облачной синхронизации.

## Файлы данных

- `%APPDATA%\AppShelf\Collections\collections.json` — определения подборок, поля, записи, теги и история.
- `%APPDATA%\AppShelf\Collections\Images\<UUID>.png` — локальные копии обложек. В JSON хранится только имя файла, не исходный путь или URL.
- `collections.json.bak` — резервная копия предыдущего сохранения. Повреждённый текущий файл не заменяется пустой подборкой автоматически.

Шаблоны создают структуру полей, но **никогда не создают пользовательские записи автоматически**. Поддерживаются восемь шаблонов: рецепты, фильмы и сериалы, игры, места и досуг, книги, идеи и занятия, список покупок, вишлист; плюс пустая подборка.

## Пример JSON, подготовленного вручную или внешним ИИ

```json
{
  "name": "Игры на потом",
  "template": "games",
  "confirmationLabel": "Поиграли",
  "fields": [
    {"key": "platform", "name": "Платформа", "type": "text"},
    {"key": "notes", "name": "Заметки", "type": "multiline"},
    {"key": "link", "name": "Ссылка", "type": "url"}
  ],
  "entries": [
    {
      "title": "Пример игры",
      "description": "Что хочется попробовать",
      "tags": ["одиночная", "приключение"],
      "values": [
        {"key": "platform", "value": "ПК"},
        {"key": "notes", "value": "Короткая заметка"}
      ]
    }
  ]
}
```

Поле `type`: `text`, `multiline` или `url`. Если дополнительные значения передаются, их `key` должны совпадать с ключами в массиве `fields`. Идентификаторы записей и подборок при импорте создаются заново; отсутствующие теги, история, списки значений допускаются. Допускается также полный документ формата `{"version": 1, "collections": [...]}`, который создаёт экспорт AppShelf.

Импортируется одна выбранная подборка из файла за операцию. Её можно создать как новую либо добавить записи в существующую подборку, если все поля совместимы по ключу или названию **и типу**. Предпросмотр показывает количество новых записей и совпадений; совпадения определяются по названию без учёта регистра и могут быть пропущены или заменены. При замене сохраняются история, отметка о приобретении и локальная обложка уже существовавшей записи.

## Импорт из скопированного текста страницы товара

В редакторе записи есть отдельное необязательное поле `sourceUrl` («Ссылка на товар») и кнопка «Из скопированного текста…».

Порядок работы: открыть товар в обычном браузере, выделить название, цену и описание, нажать **Ctrl+C**, открыть импорт в AppShelf и нажать «Вставить из буфера» → «Распознать». Перед применением все предложенные значения выводятся в редактируемых полях (название, описание, ориентировочная цена, бренд, артикул, ссылка). Пользователь проверяет и при необходимости исправляет их, затем нажимает «Применить к пустым полям».

Этот механизм не делает HTTP-запросы к Ozon, не читает сессии браузера и не обходит защиту сайта. Он работает с текстом, который пользователь явно скопировал. Извлечение данных является **эвристическим**: при копировании целой страницы вместо нужного названия и цены могут обнаружиться элементы навигации или рекламы. Лучше копировать небольшой блок товара, а не весь сайт.

Заполняются только пустые поля редактора; уже введённые значения не перезаписываются. Цены, бренд и артикул переносятся только при наличии соответствующих дополнительных полей подборки. Поле ссылки `sourceUrl` предусмотрено независимо от шаблона. Изображение невозможно гарантированно получить из обычного текстового буфера, поэтому обложку добавляют отдельно из файла или по прямой ссылке на изображение. Цена может отличаться в зависимости от региона и акций.

Прежняя кнопка прямого запроса «Заполнить из Ozon» удалена: на проверенных ссылках Ozon ответил HTTP 403, поэтому этот способ нельзя считать работающим.

## Обложки

Изображение можно выбрать из локального файла или загрузить по прямой HTTP(S)-ссылке. Оно сохраняется внутри AppShelf как PNG, независимо от исходного формата. Исходный URL или абсолютный путь в JSON не сохраняются. Ограничение исходного файла — 6 МБ; сохранённой обложки — 8 МБ.

**Экспорт отдельной подборки в JSON — текстовый.** Локальные обложки в него не включаются, чтобы не создавать неработающие ссылки на чужой компьютер. Такой файл подходит для отправки вишлиста человеку, который импортирует свою копию; это не облачная синхронизация и не совместное редактирование.

**Полный резервный ZIP AppShelf** включает `Collections/collections.json` и все обложки, на которые ссылаются записи. Незадействованные обложки не экспортируются. При восстановлении обложки проверяются и восстанавливаются вместе с данными; при ошибках файлы откатываются. Архивы старого формата без «Подборок» продолжают приниматься и не удаляют уже имеющиеся подборки пользователя. Размер общей старой части ограничен 40 МБ, обложек — 256 МБ, каждая запись ZIP — не больше 10 МБ.

Удалённые/заменённые обложки пока не стираются физически сразу, поскольку `collections.json.bak` может на них ссылаться. Безопасное освобождение места должно учитывать резервные копии.

## Ограничения обмена

JSON-экспорт подборки не включает обложки, поэтому при передаче файла на другой компьютер изображения нужно добавлять заново. Для полного переноса данных, включая локальные обложки, предусмотрен ZIP-архив. Онлайн-синхронизации, совместного редактирования и резервирования подарков пока нет.
