# Проверка AppShelf 2.19.0 RC — 20.11.2026

> Исторический отчёт предыдущей сессии, не текущий статус выпуска. Затем `2.19.0-rc.1` опубликован и оставшаяся приёмка готового EXE завершена. Актуальные результаты — в [релизном отчёте 2.19.0](RELEASE-2.19.0.md); история публикации RC — в [отчёте продолжения](RELEASE-2.19.0-CONTINUATION.md).

## Решение

**Стабильный релиз не публиковать.** GitHub CLI (`gh`) недоступен; GitHub prerelease, тег и стабильный Release в ходе этой проверки не создавались. Полный ручной прогон готового EXE, включая физическое перетаскивание мышью, не завершён.

Версия остаётся `2.19.0-rc.1`; `AssemblyVersion` и `FileVersion` — `2.19.0.0`. `main`, PR #46, лицензия, видимость репозитория и опубликованная история не изменялись. Worktree не использовался.

## Подготовка и сборка

- Исходное рабочее дерево было чистым.
- Выполнены `git fetch origin`, переход на `release/2.19.0-rc.1` и `git pull --ff-only`.
- Исходный коммит кандидата: `4f4123e`; PR #47 присутствует в истории `main` как `7c2f59e`.
- Стандартная Windows-сборка выполнена через `Build-AppShelf.cmd --no-start --no-pause`, не через .NET 8.
- Изолированные тесты перенаправляют хранилища во временные каталоги. Они не должны записывать рабочие `%APPDATA%\AppShelf`, пользовательские ярлыки или HKCU Run.

## Подтверждённые проблемы и исправления

1. `ReleaseVersion.Tests.ps1` не принимал `AssemblyInformationalVersion("2.19.0-rc.1")`: регулярное выражение допускало только стабильную версию. Исправлено разделение полной информационной версии и числовой версии сборки/списка изменений. Проверки совпадения встроенных заметок сохранены.
2. `MainBackground.Tests.ps1` проверял фон прежнего `_mainContentGrid`, который теперь намеренно прозрачен; воспроизведены четыре сбоя. Проверка перенесена на `_mainBackgroundHost`, общий для плиток и нижней панели.
3. Две аналогичные проверки галереи/перезапуска в `Ui218Probe.cs` также обновлены на общий контейнер. Приложение ради устаревших ожиданий тестов не менялось.
4. В README обнаружены буквальные `\n\n` вместо разделения абзаца и заголовка. Разметка исправлена; статусы RC в README, CHANGELOG и ROADMAP приведены к фактическому состоянию.
5. В полном прогоне `Package6Ui.Tests.ps1` прошёл 64 сценария, но дважды отклонил «О программе»: передавал RC-версию вместо числовой в поиск встроенных заметок и ожидал RC-суффикс в окне. Окно намеренно использует числовую версию сборки, что явно указано в `VersionInfo.cs`. Тест приведён к этому контракту; отдельная проверка соответствия полной RC-версии числовой сохранена.

Код приложения и `VersionInfo.cs` не изменялись.

## Итоговый регрессионный прогон и EXE

- Все **19 тестовых процессов** завершились с кодом **0** в Windows PowerShell 5.1 STA. В том числе `Package6Ui.Tests.ps1`: 66 сценариев без ошибок; `Ui219.Tests.ps1`: 10 сценариев без ошибок Dispatcher.
- Повторно проверены стандартная сборка, метаданные готового EXE и `git diff --check`.
- У общей команды запуска был ложный код 1: строки прогресса попали в массив результатов рядом с объектами, а отсутствие `ExitCode` трактовалось как неуспех. Отдельная проверка числа и кодов всех 19 тестовых процессов подтвердила успех; проверенная сводка сохранена локально как `verified-results.csv`. Ошибки тестов не игнорировались.
- Готовый `AppShelf.exe` запущен с рабочим профилем после его резервного копирования во временный каталог. Главное окно появилось и отвечает; снимок экрана проверен. Профиль не восстанавливался поверх текущих пользовательских данных.
- EXE оставлен запущенным для дальнейшей пользовательской проверки. Это не подтверждение полного ручного прогона.
- Версия EXE: `FileVersion=2.19.0.0`, `ProductVersion=2.19.0-rc.1`.
- SHA-256 проверенного локального EXE: `0E329AC729E254FA34380A587F2F4335EA00309ED6BF9D2BE3ED446713EE6BBE`.
- Опубликованного asset нет, поэтому соответствие опубликованного asset и тега не проверялось.

## Дополнительные проверки PR #47

Добавлены `tests/Ui219.Tests.ps1` и `tests/Ui219Probe.cs`. Они запускают настоящие WPF-окна в Windows PowerShell 5.1 STA, но компилируют тестовую сборку с изоляцией данных и отключённым запуском сетевых/системных действий.

| Требование | Что проверено |
| --- | --- |
| Непрерывный фон | Общий контейнер основной области и панели; просмотр снимков встроенного фона и импортированных изображений |
| Непрозрачность 0–100% | 0, 25, 50, 75, 100% для четырёх встроенных фонов и импортированных JPG/PNG |
| Читаемость карточек, кнопок, текста | Непрозрачность дочерних элементов остаётся 100%; просмотр снимков с плиткой, кнопками и статусом |
| Немедленное применение и отмена | Реальное модальное окно настроек, изменение ползунка, проверка подложки и откат после «Отмена» |
| Сохранение и старый JSON | Сохранение 37%, повторный запуск отдельного процесса, отсутствующее/null/некорректное поле без перезаписи старого JSON |
| Статус на светлом фоне | Импортированный белый PNG, отдельная тёмная подложка, просмотр снимка |
| Сообщение на 5 секунд | Настоящий DispatcherTimer, ожидание с работающим WPF Dispatcher |
| Защита от поиска и перерисовки | Поиск и `RenderTiles` не стирают активное сообщение |
| Перезапуск отсчёта | Второе сообщение переживает срок первого; затем заменяется актуальной подсказкой |
| «Подробнее» / «Свернуть» | Длинные тексты погоды и напоминаний, обе кнопки, ширины 510/600/700/1000 DIP, высота самой высокой карточки и просмотр снимков |
| Три режима панели | Компактный, категории, подробный: реальные WPF-элементы и снимки |
| Перетаскивание и окно | Существующие регрессионные сценарии; физическое перетаскивание готового EXE мышью не подтверждено |

В локальном дополнительном прогоне пройдены 10 сценариев, ошибок Dispatcher нет. Помимо стандартного изображения Windows и белого PNG проверена импортированная фотография разноцветных зонтов из локальной папки обоев HP, если она доступна. Эти изображения и снимки не добавляются в Git.

Это **не только проверка компиляции**, но и **не полный ручной приёмочный прогон**. Не подтверждены пользовательские действия в неизменённом готовом EXE, физическое перетаскивание, системный DPI и разные мониторы. Последние две проверки остаются отдельно отложенными в ROADMAP.

## Продолжение выпуска

После появления доступного авторизованного GitHub CLI:

1. Проверить актуальный коммит ветки, результат полного регрессионного прогона и метаданные заново.
2. Собрать и опубликовать prerelease с EXE из конкретного коммита; не перезаписывать уже опубликованный тег.
3. Завершить ручную проверку готового EXE.
4. Только при успешных проверках подготовить стабильные метаданные, повторить сборку и все тесты, объединить PR #48 и собрать финальный EXE из `main`.
5. Проверить соответствие тега, версии и SHA-256 опубликованного asset.
