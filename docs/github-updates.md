# Обновления AppShelf из GitHub Releases основного репозитория

**Статус на 22.11.2026:** механизм обновления выпущен в **2.19.1** ([PR #1](https://github.com/mishakov1c/app_shelf/pull/1)), а **2.19.2** опубликована как технический выпуск без новых функций. Оба EXE собраны и опубликованы GitHub Actions после успешных Windows-регрессий. Пользователь подтвердил успешное штатное обновление **2.19.1 → 2.19.2**. **Сценарий аварийного отката и восстановления при ошибках не проверен.** Основной `mishakov1c/app_shelf` — Public; исторический `app_shelf_archive` — Private.

**Оформление в 2.19.3:** штатное подтверждение установки вместо светлого Windows MessageBox использует общий тёмный диалог AppShelf. Логика получения версии, скачивания, проверки и установки не изменена. В рамках приёмки 2.19.3 пользователь отказался от отдельной проверки именно этого подтверждения; другие четыре тёмных диалога проверены вручную. Аварийный откат по-прежнему не проверен.

## Источник обновлений

- Единственный источник: **`mishakov1c/app_shelf`**, тот же репозиторий, где публикуются исходники и официальные релизы.
- GitHub API: `GET https://api.github.com/repos/mishakov1c/app_shelf/releases/latest`, без токена; репозиторий Public.
- Вложение: `https://github.com/mishakov1c/app_shelf/releases/download/<tag>/AppShelf.exe`.
- Дополнительный `AppShelf-Releases` для работы обновлений **не нужен**. Приложение не предлагает выбор имени источника и не хранит соответствующую настройку.
- Запуск вручную через **`О программе → Проверить обновления`**. Фоновые проверки пока не реализованы.

## Контракт официального релиза

1. Опубликованный **стабильный** релиз (не draft и не prerelease), тег `X.Y.Z` или `vX.Y.Z`. Первый релиз с обновлятором — `2.19.1`.
2. Вложение `AppShelf.exe`, обычная сборка Windows .NET Framework с `AssemblyName=AppShelf` и встроенной версией, совпадающей с тегом. Для самодостаточной .NET 8 сборки нужны отдельные проверки.
3. У вложения в ответе GitHub API должен быть `digest: sha256:<64 hex>`. Если он отсутствует, обновление блокируется.
4. Из описания релиза показывается текст изменений. Скачивание и установка возможны только после явного подтверждения пользователя.
5. EXE загружается из официального HTTPS URL релиза с проверкой размера, контрольной суммы и встроенной версии. Это **контроль целостности относительно GitHub**, не криптографическая подпись автора.

Официальные выпуски **2.19.1** и **2.19.2** опубликованы через [`.github/workflows/release-approved.yml`](../.github/workflows/release-approved.yml): релизный коммит запускает сборку Windows, регрессионные тесты, проверку метаданных и публикацию EXE. Ручную загрузку EXE для этих версий не использовали.

## Установка

1. Скачанный EXE помещается во временную папку `%LOCALAPPDATA%\AppShelf\Updates\...`; размер и SHA-256 проверяются до установки.
2. Существующая версия AppShelf копируется в отдельный исполняемый файл-помощник. После подтверждения обновления AppShelf закрывается, а помощник ожидает завершения основного процесса.
3. Помощник повторно проверяет SHA-256 и заменяет исполняемый файл через `File.Replace`, сохраняя прежний EXE как `AppShelf.exe.previous` для отката.
4. Затем запускается новая версия. Если замена не удалась, исходный EXE должен сохраниться; предусмотрена попытка запустить старую версию.
5. Пользовательские данные `%APPDATA%\AppShelf` обновлением не перезаписываются.

## Открытые проверки и ограничения после выпуска

- `mishakov1c/app_shelf` открыт как Public; проверка прав и принятие условий MET Norway зафиксированы в `main`. Старый `app_shelf_archive` остаётся Private. Для каждого нового EXE обеспечивается доступность исходников по точному коммиту релиза.
- Сборка и регрессионные проверки прошли через GitHub Actions для обоих релизных коммитов. Штатная установка **2.19.1 → 2.19.2** принята пользователем 22.11.2026. Аварийный откат, ошибки загрузки/записи и восстановление прежнего EXE отдельно **не проверялись**. Не считать эти сценарии завершёнными и не запускать их без отдельного согласования.
- Установка требует доступа на запись к каталогу EXE. Повышение прав без согласия не выполняется.
- Сейчас нет проверки по расписанию, принудительных обновлений, цифровой подписи файла и автоматической очистки старых временных каталогов.
- Код обновления находится в `main` и опубликован начиная с 2.19.1. В 2.19.3 изменено только оформление подтверждения установки на тёмное; основное окно обновлений и функциональность обновлятора сохранены.


## Бета-канал — в разработке для 2.23.0

- «О программе → Проверить обновления → Проверять бета-версии»: выключено по умолчанию, включая старые конфигурации. Стабильные версии доступны всегда; если одновременно доступны более новые стабильная и бета, можно выбрать любую без переключения флажка. Понижение версии автоматически не предлагается.
- С выключенным флажком сохраняется запрос `/releases/latest`. При включении проверяется список опубликованных релизов GitHub с числовым сравнением `X.Y.Z-beta.N`; тег и флаг prerelease должны соответствовать. Черновики исключаются.
- В бете числовые `AssemblyVersion` и `AssemblyFileVersion` остаются `X.Y.Z.0`, а `AssemblyInformationalVersion` и `AppShelf.ReleaseNotesVersion` содержат полный номер `X.Y.Z-beta.N`. Обновлятор сверяет номер продукта, имя сборки, размер и SHA-256; в «О программе» показывается полный номер.
- Отдельный workflow [release-beta.yml](../.github/workflows/release-beta.yml) запускает публикацию только по явному push-коммиту с заголовком `release-beta: AppShelf X.Y.Z-beta.N` в ветке `feature/**`. До этого подготовить соответствующие метаданные и раздел CHANGELOG. Windows-сборка и полный набор изолированных STA-тестов обязательны. При успехе публикуется GitHub prerelease с `--latest=false`, без merge в main. Стабильный workflow не меняется.
- Пользователь проверяет бету через встроенный обновлятор; отдельная локальная проверка агентом до её публикации не обязательна. Первая версия обновлятора с поддержкой бета-канала должна быть установлена обычным стабильным обновлением (2.23.0), либо вручную.
- Перед установкой беты используется общий механизм резервирования данных и предыдущего EXE, если включена опция копий перед обновлением (с 2.24.4); внутренний откат работает независимо. Отключение бета-канала не откатывает установленную версию; явный возврат к старой стабильной версии — отдельная идея. Реальная публикация/обновление беты и ручная приёмка пока не выполнены.
