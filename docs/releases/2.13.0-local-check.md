## Напоминания — приоритетная проверка

`DueReminders.Tests.ps1` проверяет устойчивую запись срабатывания, ошибки записи,
отложенное подтверждение, восстановление и отсутствие дубликатов.

Дополнительный `ReminderDeliveryProcess.Tests.ps1` компилирует текущие исходники,
заменяя только каталог данных и имя Mutex. Он вызывает настоящий `Program.Main`
в отдельных процессах, не подменяя таймер напоминаний или создание окна.
Необязательные внешние мониторы и звуки выключены в тестовой конфигурации.

| Сценарий | Проверка |
| --- | --- |
| Приложение работает в момент срабатывания | Назначение через 2 секунды, ожидание штатного тика DispatcherTimer и создания окна. |
| Запуск на 40 минут позже | Ежедневное напоминание уже просрочено; штатный путь запуска создаёт уведомление. |
| Запуск в трее | Главного окна не видно, но окно уведомления имеет нативный HWND, `IsWindowVisible`, не минимизировано, `Topmost` и `ShowInTaskbar`. |
| Завершение с неподтверждённым окном | Нормальное завершение приложения сохраняет `pendingAlert=true` на диске. |
| Новый процесс после завершения | Восстанавливается одно уведомление, история содержит ровно одну запись срабатывания. |
| Подтверждение | Программное нажатие «Готово» снимает `pendingAlert`; следующий процесс не показывает уведомление снова. |
| Откладывание | Быстрая кнопка переносит ту же запись срабатывания, снимает `pendingAlert`, не меняет родительское ежедневное расписание; немедленный перезапуск не показывает её раньше срока. |
| Следующее ежедневное срабатывание | Будущая дата и исходное время суток сохраняются. |
| Дубликаты истории | Проверяется количество записей при срабатывании, восстановлении, подтверждении и откладывании. |
| Сон/пробуждение Windows | Не выполнялись, чтобы не нарушать рабочее окружение. |

**Ограничение доставки:** нативная видимость окна проверена, но захват
экранных пикселей уведомления в этой сессии дал однотонное изображение.
Это не подтверждает, что человек действительно увидел уведомление на рабочем
столе, и само по себе не доказывает дефект приложения. Физический показ,
влияние блокировки сеанса/полноэкранных окон и уведомление Windows из трея
требуют ручной проверки. Запись истории не использовалась как единственное
доказательство доставки.

Причина исходного случая пользователя «09:00 → запуск около 09:40»
по-прежнему не установлена. Проверена устойчивость текущего механизма,
а не доказано объяснение того прошлого события.

## Регрессии и безопасность

- Автоматические проверки охватывают добавление/сохранение приложений, группы,
  перемещение/переименование, режим «Категории», настройки, резервные копии,
  погоду на локальных ответах, таймер, Pomodoro, трей и защиту повторного запуска.
- Анализатор Happ проверялся через изолированные тесты защитных условий,
  без отключения TUN, завершения Happ, изменения прокси/DNS или реальной сети.
- Полезность показателей реальной сети и ответы живых погодных сервисов
  не подтверждались этими тестами.
- Данные размещались только в уникальных тестовых каталогах под
  `%LOCALAPPDATA%\Temp\opencode`; реальные `apps.json`, `reminders.json`
  и пользовательские ярлыки не использовались для записи.
- Сам собранный пользовательский `AppShelf.exe` не запускался с реальным
  профилем. Запускались изолированные тестовые сборки текущих исходников.
- `.NET 8` self-contained публикация не проверялась; выполнена стандартная
  .NET Framework Windows-сборка.

## Оставшиеся ручные проверки

1. Собранный EXE: глазами подтвердить выбранный образец B и удобство интерфейса.
2. Физически перемещать ползунки, проверить плавность обновления, колесо мыши,
   перетаскивание полосы прокрутки и изменение размеров большого главного окна.
3. Проверить реальные DPI/мониторы; программное масштабирование WPF их не заменяет.
4. Убедиться глазами в показе напоминания при обычном и скрытом запуске,
   позднем старте, завершении без подтверждения и следующем запуске.
5. Проверить сон/пробуждение Windows и повторный показ отложенного уведомления
   после реального ожидания выбранного интервала.
6. Проверить реальные программы и нестандартные виртуальные/MSI/сетевые `.lnk`.
   Папка и отсутствующая цель не покрывают все виды системных ярлыков.
7. Реальные сеть/Happ, погодные сервисы, звуки, действия трея и повторный запуск.
   Не выполнять опасные сетевые действия в используемом VPN/RDP-сеансе.

ручных проверок не заявляется.
