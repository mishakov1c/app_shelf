# История изменений

Проект использует версионирование `MAJOR.MINOR.PATCH`. История версий приложения в этом CHANGELOG начинается с 2.6.1. Git-история нового чистого репозитория начинается с переноса исходников 2.19.0: прежние коммиты и обсуждения PR остались в приватном архивном репозитории и не реконструируются.


## [Unreleased]

## [2.24.0] — 2026-11-26

Первый стабильный выпуск архитектуры плагинов и свободного полотна. Объединяет изменения четырёх бет 2.24.0. Пользовательская приёмка beta.4: 17/17, без замечаний. Функциональный код принятой beta.4 не изменён.

### Плагины
- Независимые пакеты .asplugin (API v1): установка, явное доверие, включение, отключение, отдельные процессы, команды, окна, настройки, уведомления и фоновая работа. Плагины не изолированы песочницей.
- Группы виджетов и индикаторы нижней панели; размещение через менеджер плагинов, единый клик по индикатору с одним действием.
- Ручное обновление пакетов из файла или GitHub Releases для манифестов с объявленным источником. Проверки размера, SHA-256, ID, версии, источника, совместимости и доверия; страховочная копия прежнего пакета. Автоматического каталога, фонового обновления и авторизации приватных репозиториев нет.
- NotesPlugin 1.0.1 и StocksPlugin 1.0.0 — демонстрационные пакеты, не встроены в EXE. Котировки имитируются.
- Встроенная диагностика сети заменена независимым [NetworkPlugin 1.0.0 Preview](https://github.com/mishakov1c/app_shelf_network/releases/tag/v1.0.0); при первом включении предлагается перенос прежних настроек. Happ выделен отдельно и не входит в публичную поставку. RDP остаётся в ядре.

### Свободное полотно
- Единственная раскладка групп приложений и виджетов: шаг сетки, перетаскивание, изменение размеров, проверка пересечений и сохранение геометрии.
- Четыре стратегии при уменьшении окна, без перезаписи исходной раскладки. Сохранены масштаб плиток и группировка. Старые раскладки мигрируют автоматически; доступен подтверждаемый сброс расположения.
- Исправлены свёрнутые группы, границы перемещения между мониторами и перестройка при перетаскивании за край.

### Резервирование и интерфейс
- Выбор состава ZIP: данные, напоминания, подборки, фоны, виджеты, EXE, пакеты и разрешённые данные плагинов. Выборочное восстановление; исполняемые файлы извлекаются отдельно без запуска и установки.
- Сохранены страховочные копии перед обновлением и восстановлением, восстановление прерванной замены пакета. Раздельные настройки плагинов в `plugins-settings.json`.
- Тёмное оформление выпадающих списков и прокрутки; раскрытие компактной нижней панели без повторных кнопок.

### Проверки и переход
- Beta.4: локальная приёмка агента, полный Windows CI, пользовательская приёмка 17/17. Проверена совместимость опубликованного NetworkPlugin и переход между реальными EXE 2.23.0 и beta.4. Проверка обновления опубликованного самостоятельного плагина через GitHub остаётся открытой; механизм проверен на тестовых пакетах. Реальный антипростой RDP и системное восстановление Happ не проверены.
- Перед обновлением сохраните полную резервную копию профиля. При возврате к 2.23.0 сохраните отдельную копию данных новой версии; старая версия не поддерживает плагины и свободное полотно.

## [2.24.0-beta.4] — 2026-11-26

Четвёртая бета 2.24.0: стабилизация ядра, без изменения стабильного канала и без новых версий самостоятельных плагинов.

### Свободное полотно
- Единственный режим размещения групп и виджетов. Старые профили и ZIP переносятся на полотно; сохранённая геометрия имеет приоритет. Старые поля сохранены для совместимости.
- Удалены переключатели прежних режимов и пять команд авторасстановки. В быстрых настройках оставлен сброс расположения групп с подтверждением.
- Исправлены лишняя высота свёрнутых групп, доступная область полотна при изменении размеров окна и перестройка групп при перетаскивании за край. Сохранены шаг сетки, масштаб плиток и четыре стратегии адаптации.

### Интерфейс
- Тёмные выпадающие списки автоматического резервирования.
- Подробная нижняя панель заменяет компактную без дублирования кнопок.
- Индикатор плагина с единственным действием открывает его обычным кликом по всей поверхности; многокомандные индикаторы сохраняют отдельные действия.

### Менеджер плагинов
- Добавление индикаторов и виджетов из менеджера.
- Ручная проверка GitHub Releases, выбор стабильного или предварительного выпуска, просмотр изменений, скачивание и проверка SHA-256 пакета. Проверяются ID, версия, источник и совместимость API; сохраняется прежний пакет и требуется подтверждение доверия.
- Для онлайн-обновления плагин должен объявлять источник в манифесте. Старые пакеты обновляются из файла. Фоновая проверка, автоматическая установка и приватная авторизация не включены. NetworkPlugin и HappPlugin выпускаются независимо.

### Приёмка
- Функциональный коммит `746c3300053508ea23e387dc101adb119dad27c0`: локальная приёмка и Windows CI успешны; проверен переход stable → beta → stable → beta на реальных EXE. Ручное перемещение между физическими мониторами с различным DPI и сквозное обновление опубликованного самостоятельного плагина остаются отдельными проверками.
- Перед обновлением сохраните резервную копию профиля. После beta.4 — только исправления подтверждённых дефектов до стабильного 2.24.0.

## [2.24.0-beta.3] — 2026-11-26

Третья бета 2.24.0. Стабильный канал не изменён.

### Независимые плагины
- [NetworkPlugin 1.0.0 Preview](https://github.com/mishakov1c/app_shelf_network/releases/tag/v1.0.0) устанавливается отдельно через менеджер плагинов. Встроенный сетевой монитор и диагностика удалены; сетевые индикаторы теперь размещаются в панели плагинов.
- При первом явном включении NetworkPlugin предлагается перенос прежних настроек и индикаторов. Существующие настройки плагина не перезаписываются; при отказе или ошибке исходные данные сохраняются.
- Happ вынесен в отдельный приватный плагин, не входит в публичные пакеты. RDP остаётся в ядре; прежняя категория «Сеть» называется RDP. Погода и таймеры не изменены.
- NotesPlugin и StocksPlugin остаются демонстрационными пакетами. Перед установкой доверяйте только известным источникам.

### Свободное полотно
- Исправлены перенос длинных заголовков, изменение размеров карточек по абсолютному перемещению указателя и захват мыши.

### Приёмка
- На предыдущем функционально идентичном коммите пройдены локальные проверки свободного полотна, релизного NetworkPlugin, восьми сценариев миграции, независимой сборки Happ и резервирования обоих пакетов. Реальный антипростой RDP и восстановление Happ с изменением сетевых настроек Windows не проверены.
- Перед обновлением сохраните резервную копию профиля. Для этой беты NetworkPlugin устанавливается отдельно; автоматического каталога плагинов пока нет.

## [2.24.0-beta.2] — 2026-11-26

Вторая бета 2.24.0. Прежние режимы размещения и стабильный канал остаются доступны.

### Свободное полотно
- Четвёртый режим размещения: общая сетка групп приложений и виджетов. Шаг 10, 20, 30 или 40 DIP, перемещение и изменение размеров групп с предпросмотром, проверкой пересечений и сохранением геометрии.
- При уменьшении окна: адаптивная расстановка (по умолчанию), масштабирование не ниже 75%, временное сворачивание групп с раскрытием по запросу или прокрутка. Временное отображение не меняет исходные координаты; редактировать геометрию можно в основной раскладке.
- Быстрые настройки → Расставить группы: вертикально, рядами, уплотнить, по левому/правому краю, сбросить расположение. После расстановки группы можно перемещать вручную.
- При первом переходе переносится доступная геометрия прежнего режима; при пересечениях группы получают свободные места. Три старых режима и их настройки сохраняются. Длинные заголовки групп на полотне переносятся на следующую строку.

### Данные и оформление
- Координаты полотна хранятся в `plugins-settings.json` отдельно от общих настроек. ZIP сохраняет геометрию; выборочное восстановление настроек приложений и виджетов не должно заменять невыбранную часть раскладки.
- Тёмные кнопки выбора состава резервной копии. Исправлен внешний вид окон NotesPlugin, новый пакет **NotesPlugin-1.0.1.asplugin** доступен отдельно; StocksPlugin остаётся 1.0.0.
- Сеть и Happ не изменены. API плагинов предварительный. Перед откатом сохраняйте копию профиля, включая расширенные настройки.

## [2.24.0-beta.1] — 2026-11-25

Первая публичная бета архитектуры плагинов. Стабильная версия 2.23.0 остаётся доступной. API плагинов предварительный, совместимость между бетами не гарантируется.

### Плагины
- Локальные пакеты `.asplugin` с проверкой структуры и версии API, явным подтверждением доверия и запуском в отдельных процессах. Плагины не изолированы песочницей: устанавливайте только доверенные пакеты.
- Менеджер плагинов: установка, включение, отключение, запуск, перезапуск, обновление и удаление с сохранением данных. Восстановление после прерванного обновления пакета.
- Команды, собственные окна, настройки, уведомления и фоновая работа плагинов.
- Демонстрационные пакеты **NotesPlugin-1.0.0.asplugin** («Заметки») и **StocksPlugin-1.0.0.asplugin** (виджеты с имитацией котировок, без реальных биржевых данных) доступны отдельно от AppShelf.exe. Онлайн-каталога пока нет.

### Виджеты и оформление
- Группы виджетов в свободной раскладке, четыре размера виджетов, перемещение мышью, сворачивание и автоматическое обновление видимых виджетов.
- Индикаторы плагинов в нижней панели, независимо от режима размещения групп.
- Независимая высота колонок свободной раскладки, компактные группы виджетов и единое тёмное оформление списков, выпадающих списков и полос прокрутки.

### Резервное копирование и совместимость
- Отдельный файл `plugins-settings.json` для раскладки виджетов, индикаторов и новых параметров резервирования. Общие настройки остаются в `apps.json`; прежние тестовые настройки переносятся при загрузке.
- Выбор состава ручных и автоматических ZIP-копий с оценкой размера: напоминания, подборки, обложки, пользовательские фоны, виджеты, EXE, пакеты и разрешённые данные плагинов.
- Выборочное восстановление данных; отсутствующие и невыбранные компоненты не заменяются. Программы и пакеты извлекаются отдельно, без автоматической установки или запуска.
- Полные страховочные копии перед обновлением и восстановлением читаемых данных. Для повреждённого профиля сохраняются доступные исходные файлы. Резервирование данных плагинов по-прежнему требует отдельного согласия.
- Предыдущий пакет сохраняется в `BeforePluginUpdate`; автоматической очистки этих пакетов пока нет.

### Установка и ограничения
- В версии 2.23.0 включите «О программе → Проверить обновления → Проверять бета-версии» и выберите бету. Стабильный канал по умолчанию её не предлагает.
- Перед ручным возвратом к 2.23.0 полностью закройте приложение и сохраните копию всего профиля. Стабильная версия не поддерживает плагины; архивы нового формата предназначены для беты.
- Публикация выполняется только после сборки и автоматической регрессии Windows. Полная ручная приёмка новой системы резервирования остаётся частью бета-тестирования.

## [2.23.0] — 2026-11-24

### Резервное копирование и восстановление
- Автоматические полные ZIP-копии пользовательских данных раз в сутки или раз в неделю, без повторного архивирования неизменных данных. Настраиваются количество архивов и ограничение занимаемого места.
- Единая выбираемая папка резервных копий, в том числе Dropbox и OneDrive. Ручной экспорт предлагает подпапку `Manual`.
- Перед обновлением сохраняются проверенный ZIP данных и предыдущий EXE в `BeforeUpdate`. Постоянный файл .previous рядом с приложением больше не создаётся новым обновлятором; предусмотрен перенос старого .previous.
- При изменении данных во время предобновительного копирования выполняется до трёх попыток. Комплекты копий в облачной папке публикуются без переименования каталога, с маркером завершённости.
- Перед восстановлением создаётся страховочная копия в `BeforeRestore`. После успешного импорта приложение полностью завершает работу, даже если включено закрытие в трей. Локальные настройки резервного копирования сохраняются.

### Обновления
- Необязательный бета-канал (по умолчанию выключен). Стабильные выпуски доступны независимо от его настройки; финальная версия новее своих бет.
- Обновление переименованного EXE с сохранением его имени и расположения. Проверки источника, целостности и версии скачанного файла сохранены.
- Кэш результатов GitHub API на 60 секунд с сохранением между запусками, отдельными каналами и отображением времени последней успешной проверки.
- Обработка подтверждённых ограничений API 403/429 с учётом заголовков ограничения и времени следующего запроса.
- Список изменений отображается с оформлением Markdown: заголовки, списки, жирный текст, курсив, код и безопасные HTTP(S)-ссылки.

### Настройки
- Три сворачиваемые группы в окне резервных копий. Папка и статус остаются видимыми.
- «Подборки» выделены в отдельный раздел настроек; справка о закрытии окна находится в «Поведении Windows».

### Проверка
- Бета.8 прошла полную Windows-регрессию: 20/20 изолированных тестовых скриптов, в том числе 82/82 сценария Package6 и 34 проверки бета-канала.
- Пользователь подтвердил обновление переименованного EXE, Markdown, резервное копирование в Dropbox и финальную приёмку 25/25, включая восстановление ZIP и сохранение локальных настроек.
- Отдельные ручные проверки аварийного отката и принудительного исчерпания лимита GitHub не выполнялись. Переход beta.8 → стабильная 2.23.0 проверяется после публикации.

- Установщик сохраняет имя и расположение переименованного EXE. Проверяются расширение, идентичность сборки AppShelf, совпадение хеша с исходным EXE и путь родительского процесса; проверки скачанного файла сохранены.

### Периодические напоминания с тихими часами
- В редакторе доступно «Каждые N часов»: интервал от 1 до 24 часов, исходная дата и время задают первое срабатывание. Прежние записи с repeat=hourly и без repeatHours продолжают повторяться раз в час.
- Можно включить «Тихие часы» (по умолчанию 22:00–09:00) и выбрать час начала и окончания. Поддерживаются интервалы через полночь; граница начала входит в тихое время, граница окончания — нет. Тихие часы можно отключить.
- Срабатывания внутри тихих часов пропускаются без сдвига N-часовой периодичности. При позднем запуске показывается не больше одного актуального срабатывания, после чего расписание продолжается. Восстановленные и ожидающие в очереди почасовые уведомления не показываются ночью и не накапливаются до утра; явно отложенные события переносятся за пределы тихого периода.
- При первом запуске расписания внутри тихих часов поиск первого разрешённого срабатывания идёт шагами N, без изменения фазы. Если при данном интервале все возможные слоты попадают в тихие часы, редактор предупреждает и не сохраняет такое расписание.
- Новые необязательные поля repeatHours/quietHoursEnabled/quietStartHour/quietEndHour сохраняются в reminders.json, старые напоминания не меняются. Приложение версии 2.16.0 и старее не понимает repeat=hourly: перед возвратом на старую сборку сохраните копию %APPDATA%\AppShelf.


### Исправления по аудиту интеграции
- Восстановление ZIP учитывает профиль, в котором ещё нет каталога `Collections`; ошибки доступа не маскируются.
- Файл `collections.json` ограничен 16 МиБ при сохранении до замены рабочих данных; полные ZIP-архивы принимают тот же предел для документа подборок.

- Правило отбрасывания пропущенного N-часового напоминания после одного часа опоздания остаётся прежним до отдельного согласования.

- ZIP и отдельный JSON напоминаний записываются в уникальный временный файл рядом с назначением, проверяются и заменяют существующую копию через `File.Replace`, без предварительного удаления. Новое назначение создаётся через `File.Move`; временные файлы удаляются в `finally`.
- Перед заменой ZIP проходит ту же проверку, что импорт: состав, ссылки на ярлыки, корректность JSON, максимум 2000 записей, 10 МиБ на запись и 40 МиБ суммарно. Превышение лимитов не заменяет прежнюю копию.
- Страховочный каталог восстановления теперь содержит также прежние `apps.json.bak` и `reminders.json.bak`. Откат независимо пытается восстановить каждый документ и каждый затронутый ярлык; исходная ошибка импорта и ошибки отката сообщаются отдельно.
- После полного отката возвращаются прежние разрешения записи и состояния таймеров. После неполного отката сохранение старых данных из памяти остаётся заблокированным; страховочная копия сохраняется для повторного восстановления.
- Собственные ярлыки удерживаются, пока на них ссылается текущий `apps.json` или `apps.json.bak`. При следующей успешной смене `.bak` удаляются только известные копии из прежней резервной конфигурации, больше не используемые обоими JSON. Во время многофайлового восстановления очистка отложена до полного успеха.
- Неизвестные файлы в `Shortcuts` не удаляются. При нечитаемой конфигурации или ошибке удаления предпочтено удержание файлов; такие остатки и страховочные каталоги могут требовать ручной проверки. Новый формат данных и история версий файлов не вводились.

### Пакет стабильности запуска и погоды

- До чтения настроек, журналирования и запуска таймеров захватывается глобальный Mutex с SID пользователя. Он действует между сеансами одного пользователя, не объединяя независимые учётные записи. Повторный запуск показывает уведомление и не входит в рабочий код; при невозможности установить защиту запуск также прекращается без записи данных. Штатный выход освобождает Mutex; брошенный Mutex после аварии допускает новый запуск.
- Получение HTTP-ответа, чтение тела и разбор JSON погоды перенесены в фоновую задачу. Общий срок 9 секунд включает заголовки, тело и однократную попытку TLS 1.2. При истечении срока выполняется `Abort`; сетевые потоки, ответы и регистрация отмены освобождаются, позднее исключение фоновой задачи наблюдается.
- JSON ограничен 2 МиБ: проверяется заявленный размер и фактически прочитанные байты, в том числе без `Content-Length`. Неполное тело с известной длиной отклоняется. Сертификаты, HTTPS, диагностические сообщения HTTP, провайдеры и частота обновления не изменены.
- Добавлены 7 многопроцессных сценариев запуска и 11 сценариев локального HTTP-сервера с контролем Dispatcher. Тестовая сборка заменяет только границы запуска UI/уведомления, путь данных и имя Mutex; рабочие настройки и реальные погодные API не используются. На исходном `c104fc5` воспроизведены повторная запись вторым процессом и блокировка Dispatcher при медленном теле ответа.
- Пройдены все 18 новых, 6 заключительных и 80 прежних сценариев; сборка `Build-AppShelf.cmd --no-start --no-pause` успешна без предупреждений компилятора. В итоговом прогоне тайм-ауты занимали около 9 секунд, максимальный перерыв Dispatcher составил 116 мс. Сборка проекта .NET 8 не проверена: SDK в тестовой среде отсутствует.
- Заключительная проверка добавляет ещё 6 сценариев: отказ доступа к Mutex, ошибка определения SID, исключение запуска, исключение освобождения Mutex, медленная десериализация и повтор TLS в пределах общего срока. `Dispose()` Mutex выполняется во вложенном `finally`, даже если `ReleaseMutex()` выбросит исключение. Для этих тестов ошибки SID/освобождения/TLS и задержка десериализации вводятся только в изолированной тестовой сборке; отказ доступа проверяется настоящим запретом в DACL Mutex.
- Требуют ручной проверки: разные Windows-профили и сеансы, разные уровни повышения прав, реальные трей/горячая клавиша и TLS у провайдеров. Синхронный десериализатор нельзя принудительно остановить: по истечении срока ожидание завершается, а уже начатый разбор ограниченного буфера заканчивается в фоне с последующим освобождением ресурсов. Старые сборки без Mutex этой защитой не охватываются.

### Пакет достоверности погоды и удаления Яндекс Погоды

- Интеграция Яндекс Погоды полностью удалена: REST-запросы, заголовок API-ключа, модели ответов, DPAPI-класс, поле ключа и ссылки на сайт с фиксированным Кемеровом. Остались MET Norway и Open-Meteo, без ключа для личного некоммерческого использования. Старое `weatherProvider: "yandex"` нормализуется в `metno` при чтении основного JSON и `.bak`, в том числе после восстановления ZIP; остальные настройки и версия формата не меняются. Исходный JSON не переписывается самим чтением, нормализованное значение попадёт в следующее штатное сохранение. Ранее сохранённый `yandex-weather-key.dpapi` не читается, не изменяется и не удаляется.
- Отсутствующая ощущаемая температура MET Norway больше не подменяется обычной. `apparent_air_temperature` используется только при наличии; иначе текущий и дневной показатель — «н/д». Собственные формулы не вводились. При неполных точках соответствующий дневной диапазон остаётся недоступным, а не дополняется нулями.
- Числовые поля ответов и дневные массивы MET Norway/Open-Meteo различают отсутствие, JSON `null` и настоящий ноль. Обязательны текущая температура и корректные координаты города; дневные даты проверяются до использования. Отсутствующие необязательные температуры/погодные коды показываются как «н/д», вероятность осадков — прочерком. Работающая обработка отсутствия осадков, настоящего нуля и отрицательных температур сохранена.
- MET Norway отклоняет неверное время точки и отсутствие обязательного `instant.details` в отображаемом периоде: такие записи больше не исчезают молча с подстановкой более поздней точки вместо текущей погоды или показом неполного диапазона.
- MET Norway получает IANA ID зоны из уже используемого геокодера. На .NET Framework он сопоставляется с Windows ID через системную ICU, после чего каждая UTC-точка переводится через `TimeZoneInfo` с правилами DST. Встроенное Кемерово использует Windows-зону UTC+7. Неизвестная зона или недоступная системная ICU дают явную ошибку, без часового пояса компьютера и без нового сервиса, пакета или таблицы городов. Для IANA-сопоставления на Framework нужна Windows 10 1903+; .NET 8 может распознавать ID напрямую.
- Метки дневного прогноза показывают даты города вместо безусловного «Сегодня» у первой строки. Диапазоны MET Norway явно подписаны как диапазоны по точкам прогноза, не измеренные суточные экстремумы.
- Актуальность результата и ошибки проверяется по городу, провайдеру и ревизии погодных настроек. При изменении настроек устаревшие данные очищаются сразу; после завершения старого запроса выполняется одно обновление новых настроек, без бесконечного повтора при ошибке. Переключение A→B→A и отключение погоды также аннулируют старый результат.
- Для MET Norway сохраняются только отметки времени попыток по городу в текущем процессе, не погодные данные: повторный запрос не выполняется раньше 3 часов, включая ошибки и возврат к прежнему источнику. Эти отметки не сохраняются между запусками и не объединяют разные написания города. Частота Open-Meteo остаётся 30 минут; автоматического переключения источников и нового погодного кеша нет.
- Документация: [MET Norway](https://api.met.no/weatherapi/locationforecast/2.0/documentation), [модель MET](https://docs.api.met.no/doc/locationforecast/datamodel.html), [геокодер Open-Meteo](https://open-meteo.com/en/docs/geocoding-api), [системная ICU Windows](https://learn.microsoft.com/en-us/windows/win32/intl/international-components-for-unicode--icu-). В журнале MET заявлено добавление `apparent_air_temperature` в августе 2026, но опубликованная схема/страница модели ещё не перечисляют его: наличие поля не предполагается обязательным.

Повторно пройдены все 104 прежних сценария; стандартная сборка .NET Framework и `git diff --check` успешны. Режим тестов `-WithoutIcu` вызывает настоящий отказ загрузки DLL только в тестовой сборке и проверяет явную ошибку для IANA ID при сохранении работы встроенной Windows-зоны.
