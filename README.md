# AppShelf

AppShelf — панель быстрого запуска приложений и сайтов для Windows (C# / WPF). Объединяет ярлыки, группы, напоминания, «Подборки», погоду и дополнительные инструменты в одном окне; поддерживает работу из системного трея.

**Последний стабильный выпуск: [2.21.1](https://github.com/mishakov1c/app_shelf/releases/tag/2.21.1) от 23 ноября 2026 года.** Готовый `AppShelf.exe` доступен в [GitHub Releases](https://github.com/mishakov1c/app_shelf/releases/latest). Исходный код открыт под GPL-3.0-only.

## Начало работы и обновления

1. Скачайте `AppShelf.exe` из последнего стабильного выпуска GitHub Releases или соберите приложение по инструкции ниже.
2. Запустите EXE в Windows 10/11 с .NET Framework 4.8. Основные настройки сохраняются отдельно от EXE, в `%APPDATA%\AppShelf`.
3. Добавляйте программы и сайты кнопкой «+ Добавить» или перетаскиванием файлов в окно. Группы и поиск помогают организовать плитки.

Начиная с **2.19.1** обновления можно проверять вручную через **«О программе → Проверить обновления»**. При подтверждении AppShelf загружает стабильный выпуск, проверяет размер, версию и SHA-256 и сохраняет прежний EXE. Автоматической фоновой установки нет. Штатный переход **2.19.1 → 2.19.2** проверен пользователем; аварийный откат при сбое установки отдельно не проверялся. Выпущенный 2.19.0 встроенного обновлятора не содержит. Подробности — в [документации обновлений](docs/github-updates.md).

## Что нового в 2.21.1

Исправлено свободное размещение групп на небольших мониторах: верхние и нижние зоны теперь занимают высоту по содержимому, а средняя использует оставшееся пространство. Если все группы помещаются, общая вертикальная прокрутка не появляется; если места недостаточно — она сохраняется и плитки не обрезаются. При изменении высоты окна расположение пересчитывается автоматически. Новых настроек и изменений формата пользовательских данных нет.

## Что появилось в 2.21.0

- **Три режима размещения групп:** «Список», «Автоматическая сетка» и «Свободное размещение» по девяти зонам. Их можно переключать через «⋯ → Быстрые настройки → Размещение групп».
- **Гибкая ширина:** в списке группы могут занимать всю ширину или подстраиваться по содержимому, с выравниванием слева, по центру, справа либо чередованием. Сетка автоматически размещает группы рядом и переносит по ширине окна.
- **Свободное размещение:** зона по умолчанию выбирается наглядной сеткой 3×3, а отдельную группу можно переместить мышью или через контекстное меню заголовка.
- **Упрощённые настройки:** неподходящие для выбранного режима параметры скрыты; переключение не стирает ранее выбранные значения и совместимо со старым `apps.json`.

В **2.20.0** были объединены разделы настроек и добавлены независимые действия для нескольких одновременно сработавших напоминаний. В **2.19.3** обычные подтверждения и предупреждения получили тёмное оформление, а в **2.19.0** появилась отдельная регулировка непрозрачности нижней панели. Полная история — в [CHANGELOG.md](CHANGELOG.md).

## Основные возможности

- **Плитки и группы:** запуск программ, папок и HTTP(S)-сайтов; три варианта отображения плиток (компактный, обычный, с подписями), масштаб 75–125%; группировка, поиск, перетаскивание и три режима размещения групп.
- **Оформление:** тёмная тема, встроенные и собственные JPG/PNG-фоны, галерея миниатюр, непрозрачность групп и нижней панели, запоминание размеров и положения основного окна и размеров дополнительных окон.
- **Нижняя панель:** подробный, компактный и категорийный режимы; настраиваемая видимость категорий «Сеть», «Погода», «Время», быстрые индикаторы и доступ к окнам инструментов.
- **Напоминания:** разовые и повторяющиеся события (день, неделя, выбранные дни, будни/выходные, каждые N часов, месяц, год), тихие часы, отложить/завершить, импорт и экспорт JSON.
- **Подборки:** восемь шаблонов (включая список покупок и вишлист), собственные поля, теги, обложки, случайный выбор, история и передача через JSON. Синхронизации и совместного редактирования пока нет.
- **Инструменты:** таймер, Pomodoro, погодный прогноз с MET Norway или Open-Meteo и локальным кешем до 24 часов, диагностика сети и дополнительные действия для Happ/TUN, RDP-антипростой.
- **Управление:** `Ctrl+O` — добавить, `Ctrl+F` — поиск, `Ctrl+Alt+Space` — показать/скрыть окно; автозапуск с Windows, запуск свёрнутым в трей, переключатели звуков.
- **Данные:** ZIP-экспорт и восстановление настроек, собственных ярлыков, напоминаний, подборок и пользовательских фонов. Установленные приложения в ZIP не включаются.



## Системные требования

Для стандартной сборки и запуска:

- Windows 10 или Windows 11;
- .NET Framework 4.8 или совместимая более новая версия .NET Framework 4.x;
- права администратора не требуются для обычной сборки и запуска, но Windows может запросить повышение прав для отдельных действий.

Для альтернативной self-contained сборки из `Publish-SelfContained.cmd`:

- Windows x64;
- .NET 8 SDK на компьютере, где выполняется сборка.

Self-contained EXE включает среду выполнения .NET 8, поэтому устанавливать её на конечном компьютере не требуется. В рамках первоначальной публикации проверена стандартная сборка .NET Framework; self-contained публикация не проверялась, поскольку .NET 8 SDK в локальной среде не установлен.

## Сборка

### Стандартная сборка .NET Framework

Запустите в корне проекта:

```cmd
Build-AppShelf.cmd --no-start --no-pause
```

Скрипт использует компилятор C# и WPF-сборки установленного .NET Framework. Результат создаётся в корне проекта: `AppShelf.exe`.

Без параметров скрипт после успешной сборки запускает приложение, а при ошибке ожидает нажатие клавиши:

```cmd
Build-AppShelf.cmd
```

Параметры `--no-start` и `--no-pause` предназначены для автоматической сборки и удобного получения EXE без запуска GUI. Ошибка компиляции возвращает ненулевой код завершения.

### Self-contained сборка .NET 8

На компьютере с установленным .NET 8 SDK выполните:

```cmd
Publish-SelfContained.cmd
```

Результат будет находиться в `publish\AppShelf.exe`. Используются `win-x64`, один файл и включённая среда выполнения.

### GitHub Actions

Workflow `.github/workflows/build-windows.yml` выполняет стандартную сборку на Windows runner при `push`, pull request и ручном запуске. При успехе `AppShelf.exe` загружается как artifact с именем `AppShelf-<SHA коммита>`. Artifact содержит только EXE и не содержит пользовательские настройки. Автоматический Release не создаётся.

## Запуск

1. Соберите приложение или получите EXE из проверенного релиза либо GitHub Actions artifact.
2. Запустите `AppShelf.exe`.
3. Для полного завершения работы используйте пункт **«Выход»** в меню значка AppShelf в системном трее, а не только скрытие окна.

Для self-contained публикации можно переносить полученный EXE на другой поддерживаемый Windows x64-компьютер. Стандартный EXE требует установленный совместимый .NET Framework.

## Автозапуск с Windows и звуки (с версии 2.8.0)

Откройте **«⋯ → Настройки…»**. В разделе **«Запуск Windows»** можно включить автозапуск AppShelf при входе в текущую учётную запись Windows и отдельно выбрать режим **«При автозапуске сразу скрывать в трей»**. Никакого автозапуска по умолчанию нет. При отключении автозапуска соответствующая запись в HKCU Run удаляется. Путь к запускаемому EXE берётся из текущего расположения программы: если переместили файл, откройте настройки и сохраните их снова.

В разделе **«Звуковые уведомления»** есть общий переключатель звуков AppShelf и индивидуальные переключатели для Помодоро и напоминаний. По умолчанию сохраняется старое поведение: звук Помодоро включён, дополнительный звук напоминаний выключен. Даже без звука само уведомление останется видимым; системный звук уведомления Windows при показе сообщения в трее регулируется настройками ОС.

Автозапуск хранится в Windows (не в резервной копии ZIP). Звуковые настройки сохраняются вместе с остальными параметрами в `apps.json` и входят в ZIP-резервную копию.

## Где хранятся пользовательские настройки

Рабочие данные находятся в каталоге:

```text
%APPDATA%\AppShelf
```

Основные файлы и каталоги:

| Путь | Содержимое |
| --- | --- |
| `apps.json` | Программы, сайты, группы, оформление, положение окна, настройки погоды и других модулей. |
| `apps.json.bak`, `apps.json.tmp` | Предыдущая версия настроек и временный файл атомарной записи. |
| `reminders.json` | Напоминания. |
| `reminders.json.bak`, `reminders.json.tmp` | Предыдущая версия напоминаний и временный файл записи. |
| `Shortcuts\` | Собственные копии ярлыков `.lnk` и `.url`, которыми управляет AppShelf. |
| `yandex-weather-key.dpapi` | Может остаться от старых сборок. Больше не используется; приложение его не читает, не изменяет и не удаляет. |
| `error.log` | Журнал ошибок с локальным временем и стеком; автоматической ротации нет. |
| `Backups\` | Страховочные копии, создаваемые перед восстановлением данных. |

Файлы из этого каталога не предназначены для Git. Они могут содержать персональные напоминания, список установленного ПО и пользовательские пути.

## Резервное копирование и перенос данных

В меню **«⋯ → Экспорт / импорт данных…»** доступны следующие операции:

1. **Экспортировать всё в ZIP** — сохраняет приложения, группы, настройки, напоминания и собственные ярлыки. Пути к внутренним ярлыкам в архиве становятся относительными.
2. **Восстановить из ZIP** — сначала проверяет архив и создаёт копию текущих данных в `%APPDATA%\AppShelf\Backups\before-restore-...`, затем выполняет импорт. При ошибке записи приложение пытается восстановить прежние данные. После успешного импорта AppShelf закрывается, его необходимо запустить заново.
3. **Экспортировать напоминания в JSON** — сохраняет отдельный файл `AppShelf-reminders.json`.
4. **Импортировать напоминания из JSON** — после подтверждения заменяет текущие напоминания и сохраняет прежний файл как `reminders.json.bak`.
5. **Открыть папку данных** — открывает каталог `%APPDATA%\AppShelf` для ручного доступа.

Перед переносом рекомендуется сделать ZIP-экспорт и дополнительно сохранить копию исходного каталога данных.

**Ограничения переноса:**

- в ZIP входят собственные ярлыки, но не сами EXE установленных программ;
- на другом компьютере программы должны быть установлены, а абсолютные пути к ним могут потребовать исправления;
- посторонние файлы, включая оставшийся от старых сборок файл ключа, не включаются в резервные копии;
- экспортированные архивы и JSON могут содержать личные данные, поэтому их нельзя публиковать.

## Добавление программ и сайтов

### Программы

Поддерживаются файлы `.exe`, `.lnk`, `.bat`, `.cmd`, `.url`, `.msc` и `.com`. Перетащите файл из Проводника в главное окно либо нажмите **«+ Добавить → Приложение или ярлык…»** (также доступно через `Ctrl+O`); можно выбрать несколько файлов. Ярлыки `.lnk` и `.url` копируются в каталог данных AppShelf, оригиналы не изменяются. Папку можно добавить через «+ Добавить → Папку…».

### Сайты

Нажмите **«+ Добавить → Сайт по ссылке…»**, введите адрес и название. Если схема не указана, используется HTTPS. AppShelf создаёт собственный `.url`-ярлык, поэтому работа с группами и ZIP-резервными копиями остаётся прежней. Ранее добавленные вручную `.url` также поддерживаются.

Favicon загружается в фоне с сайта по `/favicon.ico` либо из HTML-ссылок на иконки, с ограничением времени и размера. До загрузки или при ошибке отображается стандартная иконка Windows. Значки кешируются в `%APPDATA%\\AppShelf\\SiteIcons` и не включаются в ZIP; при необходимости загружаются повторно.

В контекстном меню плитки сайта можно **посмотреть, скопировать или изменить URL**. Поддержан приём ссылок из браузера перетаскиванием, но конкретные браузеры могут использовать разные форматы; необходимо реальное пользовательское тестирование.

## Запуск от администратора

Используйте пункт **«Запустить от администратора»** в контекстном меню плитки для разового запуска либо включите **«Всегда запускать от администратора»**. Windows использует стандартный запрос UAC; подтверждайте его только для доверенных программ. Поддерживаются EXE, COM, BAT, CMD, MSC и обычные `.lnk` на эти файлы. Для `.url`, папок и виртуальных ярлыков без доступной цели повышенный запуск не поддерживается.

Сам AppShelf не требует постоянного запуска с повышенными правами. Для отдельных программ Windows также может запрашивать UAC согласно их собственным требованиям.

## Группы и настройки внешнего вида

Включите **«⋯ → Быстрые настройки → Группировка приложений»** и создайте группу через **«⋯ → Создать группу»**. Плитку можно перемещать через контекстное меню «Переместить в группу» или мышью. Маркер `⋮⋮` используется для перестановки групп; контекстное меню заголовка — для переименования и удаления. Сайты и программы размещаются в одних и тех же группах. При удалении группы плитки переходят в «Без группы»; исходные программы не удаляются.

В **«⋯ → Настройки… → Внешний вид»** доступны три вложенных подраздела:

- **Плитки и группы:** отображение и масштаб плиток, включение группировки, непрозрачность групп и выбор режима размещения.
- **Фон главного окна:** встроенные и пользовательские фоны. Галерея быстрого выбора доступна также через «⋯ → Выбрать фон…».
- **Нижняя панель:** режимы «Подробная», «Компактная», «Категории», видимость карточек и непрозрачность подложки. Настройки, не относящиеся к текущему режиму, скрываются, но сохраняют значения.

В 2.21.0 доступны следующие режимы размещения:

- **Список:** группы идут сверху вниз. В настройках «Ширина групп» выбирается «На всю ширину» или «По содержимому». Во втором случае можно выбрать выравнивание: левый край, центр, правый край, чередование. Для отдельной группы выравнивание задаётся через контекстное меню заголовка.
- **Автоматическая сетка:** группы располагаются рядом по доступной ширине окна и автоматически переносятся на новые строки. Настройки ширины и выравнивания списка в этом режиме не применяются.
- **Свободное размещение:** рабочая область разделена на девять зон. «Положение новых групп по умолчанию» выбирается через сетку 3×3; отдельную группу можно переместить в другую зону мышью либо через контекстное меню заголовка.

Режим быстро переключается в **«⋯ → Быстрые настройки → Размещение групп»**; выбранный вариант отмечается галочкой. В 2.21.1 свободный режим дополнительно оптимизирован для небольших экранов: при наличии свободного места нижние группы больше не создают лишнюю прокрутку. При выключенной группировке этот пункт недоступен. Все подробные параметры остаются в основных настройках. Переключение режимов сохраняет значения неактивных параметров, а для прежних пользовательских данных сохраняется исходное вертикальное размещение.

Команда **«Убрать из AppShelf»** удаляет плитку и, если применимо, её собственный ярлык в данных AppShelf, но не удаляет установленную программу или оригинальный ярлык.

## Напоминания

1. Нажмите «Напоминания» на нижней панели, затем «Добавить напоминание».
2. Введите название (до 200 символов), выберите дату в календаре и установите часы и минуты в двух полях `HH:mm`. Можно вводить цифры, нажимать стрелки рядом с нужным полем или клавиши ↑/↓; шаг минут — 1. На границах 00–23 и 00–59 значения останавливаются без переноса даты или соседнего поля. Tab переходит между часами и минутами, одна цифра дополняется нулём. Для нового напоминания подставляется текущее время + 30 минут. Дату также можно ввести вручную в формате текущей культуры Windows.
3. Выберите повтор: один раз, ежедневно, еженедельно, по будням, по выходным, по выбранным дням недели, каждые N часов (1–24), ежемесячно или ежегодно. Нажмите «Сохранить». Enter сохраняет, «Отмена»/Escape закрывает редактор без сохранения.
4. Для изменения используйте «Изменить» в списке. Ошибка ввода не закрывает форму и не стирает значения. При ошибке записи исходное напоминание остаётся без изменений; можно повторить сохранение или отменить правки.

Ежемесячный повтор сохраняет исходное число месяца: 31 января → 28/29 февраля → 31 марта → 30 апреля. Ежегодное 29 февраля переносится на 28 февраля в обычные годы и возвращается к 29 февраля в високосные. Это календарные месяцы/годы, не интервалы 30/365 дней. Изменение только названия или времени не сбрасывает исходное число; изменение даты или типа повтора задаёт новый отсчёт.

Напоминания используют местное время Windows. После запуска или сна просроченное напоминание обрабатывается один раз, а следующий повтор переносится сразу на будущую дату без отдельного уведомления за каждый пропущенный период. Запись нового состояния выполняется перед постановкой уведомления в очередь. Сбой записи оставляет напоминание просроченным для повторной попытки.

С версии 2.20.0 несколько одновременно сработавших напоминаний обрабатываются **независимо**: каждое имеет свои действия «Готово» и отложить (быстрый интервал либо «Ещё…»). Закрытие общего окна **не подтверждает** оставшиеся карточки — они сохраняются и повторно показываются после запуска. Подтверждённые срабатывания не возвращаются, а индивидуальное откладывание не сбивает расписание повторяющегося напоминания. Для восстановления незавершённого события используется необязательный признак `pendingAlert`, добавленный ещё в 2.13.0.

Файл `reminders.json` сохраняет версию 1 и прежние поля. Для календарных повторов добавлены необязательные `repeatDay` и `repeatMonth` (месяц нужен ежегодному повтору). Старые `once`, `daily`, `weekly` читаются без миграции; JSON-экспорт/импорт и ZIP сохраняют новые поля. При отсутствии календарных полей исходная дата выводится из `dueLocal`; восстановить утраченное исходное число по одной уже сокращённой дате невозможно. Старые сборки не поддерживают новые `monthly`/`yearly`: перед возвратом к ним сохраните резервную копию.

Кнопки редактора закреплены отдельно от прокручиваемых полей. Реальные настройки DPI 100%, 125%, 150% и перемещение между мониторами требуют ручной проверки; автоматические проверки масштабирования содержимого не заменяют её.

## Диагностика сети и восстановление после Happ

**Независимый проект.** AppShelf не связан с разработчиками Happ, не является официальным продуктом Happ и не одобрен ими. Название Happ, имена процесса и сетевого адаптера (`Happ`, `happ-default-tun`) упоминаются исключительно для описания необязательных функций диагностики и восстановления сети. Права на название и товарные знаки Happ принадлежат их правообладателям. AppShelf не распространяет клиент Happ и не гарантирует совместимость с ним.

Начиная с 2.14.0 открывайте общую диагностику через индикатор **«Сеть»**. Здесь доступны сведения об интернете, DNS, системном прокси и активных сетевых адаптерах, подробный отчёт и две настраиваемые проверки ICMP/HTTPS/TCP (изначально `1.1.1.1` и `ya.ru`). Настройки целей доступны в разделе «Сеть». Дополнительные действия Happ выделены отдельно и требуют подтверждения. Результат отдельных проверок не гарантирует работу браузера: тот может использовать собственные сетевые настройки или расширения.

Кнопка **«Отключить Happ TUN…»** по-прежнему отключает только адаптер; сам Happ не завершается. Новая кнопка **«Восстановить интернет…»** запускает отдельные шаги, каждый с собственным подтверждением:

1. Принудительное завершение найденных процессов именно с именем `Happ`, если пользователь согласен. Несохранённые данные могут быть потеряны.
2. Отключение `happ-default-tun` с запросом UAC, если пользователь согласен. VPN и RDP могут оборваться.
3. Если в WinINET включён **исключительно локальный** ручной прокси (`localhost` или loopback-IP без сторонних узлов и PAC), предлагается временно его выключить. Принадлежность прокси Happ автоматически не подтверждается; пользователь принимает решение самостоятельно. Адрес сервера не стирается. Кнопка **«Вернуть прокси…»** возвращает состояние в течение текущего открытия анализатора, при этом настройки не должны измениться извне.
4. При ошибке разрешения DNS отдельно предлагается `ipconfig /flushdns` (очищает кеш; DNS-серверы не меняются). По завершении запускаются проверки заново.

**Ограничения:** AppShelf не сбрасывает Winsock, сторонние прокси, PAC, браузерные расширения, чужие маршруты и DNS-настройки. Он не гарантирует восстановление связи, если сбой произошёл в сетевом фильтре, приложении или провайдере. При использовании удалённого доступа не отключайте TUN, через который идёт текущая сессия. Ручная проверка на Windows обязательна.

Тест защитного фильтра прокси (без изменения сетевых настроек) после сборки:

```powershell
powershell.exe -NoProfile -STA -File tests\HappRecovery.Tests.ps1
```

## Какие функции требуют сети

| Функция | Сетевое взаимодействие |
| --- | --- |
| Погода | Обращается к выбранному API: MET Norway или Open-Meteo. |
| Поиск координат города | Для городов, кроме встроенного варианта Кемерова, используется геокодирование Open-Meteo, включая случаи выбора другого погодного источника. |
| Открытие сайтов | Для загрузки содержимого сайта нужна сеть; AppShelf передаёт адрес системному обработчику URL. |
| Диагностика задержки | Выполняет сетевые проверки к внешним адресам. |
| Happ/TUN и RDP | Сетевое взаимодействие зависит от настроенного профиля, подключения и выполняемого действия. |

Локальные ярлыки, группы, настройки, Pomodoro и сохранённые напоминания не требуют постоянного подключения к интернету. Для погоды доступен **кеш последнего успешного прогноза до 24 часов** (отдельно для MET Norway и Open-Meteo); недельного офлайн-хранилища нет.

### Особенности погодных источников

- **MET Norway** не требует ключа. Текущая температура является ближайшим прогнозным интервалом, а не обязательно результатом измерения. Для регионов вне Северной Европы частота запросов ограничена не чаще одного раза в 3 часа. Вероятность осадков может отсутствовать.
- **Open-Meteo** оставлен как альтернативный источник. Доступность любого внешнего сервиса из конкретной сети не гарантируется.
- Интеграция Яндекс Погоды удалена начиная с версии 2.6.2. Старое значение `weatherProvider: "yandex"` при чтении заменяется на `metno` в памяти; остальные настройки и версия JSON сохраняются. Ранее сохранённый файл ключа остаётся нетронутым.
- Отсутствующие необязательные температуры обозначаются «н/д», отсутствие вероятности осадков — прочерком. Реальные `0 °C` и отрицательные значения сохраняются. Если нет обязательной текущей температуры, прогноз отклоняется с ошибкой.
- MET Norway группирует точки по календарю выбранного города, включая DST. IANA ID приходит из уже используемого геокодирования, для .NET Framework сопоставляется системной ICU Windows 10 1903+; .NET 8 может распознавать его напрямую. Если пояс не определён, прогноз отклоняется, а не пересчитывается в пояс компьютера. Встроенное Кемерово использует системную зону UTC+7.
- Диапазоны MET Norway рассчитаны по доступным точкам прогноза, а не по измеренным суточным экстремумам. Если часть температурных точек неполна, соответствующий диапазон недоступен. Метки дней показывают конкретные даты города.
- Результаты и ошибки устаревших запросов не применяются после изменения города или источника. MET Norway не опрашивается повторно для того же города раньше 3 часов, включая неуспешные попытки и переключение источников; сохраняются только отметки времени попыток в текущем процессе, не погодный кеш.

## Известные ограничения

- Приложение предназначено только для Windows; WPF не является кроссплатформенным интерфейсом.
- Проверки зависят от версии и ветки: выпущенный 2.20.0 прошёл указанные в `CHANGELOG.md` локальные и ручные сценарии, но это не заменяет проверки на всех сочетаниях DPI, мониторов и конфигураций; ветка 2.21.0 требует отдельной приёмки.
- Автотесты находятся в `tests` и выполняются Windows PowerShell 5.1 в STA. GitHub Actions проверяет компиляцию и создаёт artifact, но не заменяет эти тесты и пользовательскую проверку.
- Работа погоды зависит от доступности внешних API. Кеш успешного прогноза ограничен 24 часами; автоматическое переключение на другой источник при сбое не заявлено.
- Напоминания и Pomodoro требуют запущенного AppShelf. Текущее состояние отсчёта Pomodoro после перезапуска не восстанавливается. Закрыть приложение можно также крестиком главного окна.
- Анализ таблицы маршрутов Happ ограничен IPv4; отключение TUN может разорвать VPN/RDP, обратного включения из приложения нет. Антипростой RDP отправляет F15 и не гарантирует отмену серверных политик.
- Новые сборки допускают один экземпляр на Windows-пользователя между сеансами; старые сборки без этой защиты могут конкурировать за данные и горячую клавишу.
- Резервная копия не заменяет установку программ на новом компьютере.
- Для действий с повышенными правами и управления отдельными системными функциями могут потребоваться подтверждение UAC и соответствующие права пользователя.
- Сведения о выпущенных изменениях находятся в `CHANGELOG.md`; будущие задачи — в `ROADMAP.md`.

Дальнейшие направления развития перечислены в [ROADMAP.md](ROADMAP.md), история изменений ведётся в [CHANGELOG.md](CHANGELOG.md).
